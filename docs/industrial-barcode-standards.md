## 一、 工业条码标准体系分层模型

工业条码从“物理光电识别”到“上层业务系统消费”遵循严格的分层处理架构：

```
+-----------------------------------------------------------------------------------+
| 层级 5: 业务与算法层 (Business & Algorithm Layer)                                  |
| 例如：加权校验位算式 (Luhn/Modulo 10/43)、日期有效性区间校验、MES/ERP 工单匹配      |
+-----------------------------------------------------------------------------------+
| 层级 4: 行业垂直规范 (Sector-Specific Standards)                                 |
| 例如：AIAG B-10 / VDA 4994 (GTL) / MIL-STD-130 UID / UDI / SEMI T7 / ATA 2000     |
+-----------------------------------------------------------------------------------+
| 层级 3: 数据标识与语义层 (Identifier & Semantic Layer)                             |
| 例如：GS1 AI (01, 10, 17, 21), ASC MH10.8.2 DI (1P, Q, S, 1T, V, 3S, 4S)          |
+-----------------------------------------------------------------------------------+
| 层级 2: 数据语法与外壳传输层 (Data Syntax & Envelope Layer)                        |
| 例如：ISO/IEC 15434 ([)> + RS + 06 + GS ... RS + EOT), 紧凑拼接, 自定义分隔符     |
+-----------------------------------------------------------------------------------+
| 层级 1: 物理载体与码制编码层 (Physical Symbology Layer)                           |
| 例如：Data Matrix ECC 200, Code 128, QR Code, PDF417, DPM 激光/打点刻蚀           |
+-----------------------------------------------------------------------------------+
| 层级 0: 硬件解码与 I/O 码流层 (Hardware & Reader Stream Layer)                    |
| 例如：ISO/IEC 15424 AIM ID (]d1, ]C1), ASCII 控制字符 (\x1D, \x1E, \x04, \x0D)    |
+-----------------------------------------------------------------------------------+
```

## 二、 物理码制标准（载体层）

### 1. 一维条码体系 (1D Symbologies)

| 码制名称 | 国际/行业一级标准 | 字符集能力 | 典型应用领域 | 结构特征与校验机制 |
| :--- | :--- | :--- | :--- | :--- |
| **Code 128** | **ISO/IEC 15417:2007** | 完整 128 ASCII 字符集（A/B/C 三子集动态切换，Code C 模式支持纯数字双位压缩） | 工业制造物料标签、仓储拣货、内部物流 | 高密度连续型；含加权 Modulo 103 内部校验；双向可读；起始/终止符保护。 |
| **GS1-128** *(原 UCC/EAN-128)* | **ISO/IEC 15417** / GS1 General Specs | 128 ASCII（首字符强制包含 `FNC1` 标识） | 供应链物流外箱（SSCC-18）、批次追踪、托盘标 | 物理上为 Code 128，但在起始符后紧跟 FNC1 声明其遵循 GS1 AI 语义体系；后续 FNC1 映射为 `<GS>`。 |
| **Code 39** *(3 of 9)* | **ISO/IEC 16388:2007** / ANSI/AIM BC1 / MIL-STD-1189 | 43 字符（大写 A-Z、数字 0-9、7 个标点 `- . $ / + % 空格`） | 汽车零部件（早期 AIAG）、国防军工、老旧工厂 | 离散型（字符间有间隙）；每个字符 9 个单元（3宽6窄）；起始/终止符固定为 `*`；可选 Modulo 43 校验。 |
| **Code 39 Full ASCII** | **ISO/IEC 16388 Annex A** | 全 128 ASCII 字符 | 特殊扩展应用 | 通过 `+`, `%`, `$`, `/` 与字母组合转义 ASCII，编码密度显著降低。 |
| **Code 93** | **ANSI/AIM BC5** | 原生 47 字符，组合支持全 128 ASCII | 电子制造、快递面单（如加拿大邮政）、高密度小标 | 连续型；密度高于 Code 39；采用双校验字符（Check C 和 Check K，Modulo 47）。 |
| **Interleaved 2 of 5 (ITF / ITF-14)** | **ISO/IEC 16390:2007** | 仅纯数字（0-9），字符数必须为**偶数** | 瓦楞纸箱外包装、物流分拣（ITF-14 箱码） | 连续型双向可读；条和空均用于编码数字（奇数位由条编码，偶数位由空编码）；耐低精度印刷。 |
| **EAN-13 / EAN-8 / UPC-A / UPC-E** | **ISO/IEC 15420:2019** | 纯数字（13/8/12/6 位定长） | 消费品零售 POS 结算、商品外包装 | 定长数字串；末位为加权 Modulo 10 校验位（奇偶位权值 1/3）；采用左右分区结构。 |
| **Codabar (NW-7)** | **AIM-BC3-1995** | 数字 0-9，标点 `- $ : / . +`，起始/终止符 `A/B/C/D` | 医疗血液化验、血库血袋、图书馆借还系统 | 离散型，起始/终止符具备状态标识功能（不同组合代表不同业务动作）。 |
| **GS1 DataBar** *(原 RSS)* | **ISO/IEC 24724:2011** | GTIN + 属性数据 | 散装生鲜称重、微型医疗耗材 | 高密度紧凑条码，支持全向扫描；可堆叠形成 DataBar Expanded。 |

### 2. 二维条码体系 (2D Matrix & Stacked)

| 码制名称 | 国际/行业一级标准 | 结构与容错机制 | 工业核心地位与场景 | 编码与识读特征 |
| :--- | :--- | :--- | :--- | :--- |
| **Data Matrix (ECC 200)** | **ISO/IEC 16022:2006** | Reed-Solomon 纠错 (ECC 200)，支持正方形 (10x10 ~ 144x144) 与长方形 (8x18 ~ 16x48) | **工业制造、汽车零部件、半导体晶圆、医疗器械 DPM 的第一核心** | 寻像图形由实线“L”型寻像边（Finder Pattern）与交替时钟边构成；单位面积信息密度最高。 |
| **QR Code (Model 2 / Micro QR)** | **ISO/IEC 18004:2015** | Reed-Solomon 纠错（L 7%, M 15%, Q 25%, H 30%），3 个角定位图案 | 日本/亚洲汽车供应链（DENSO/JAMA）、消费电子、智能制造看板 | 全向极速寻像；原生支持日文/汉字编码；Micro QR 仅有 1 个寻像角，专用于微型表面。 |
| **PDF417 / MicroPDF417** | **ISO/IEC 15438:2015** | 堆叠式二维条码（多层线性行堆叠），Reed-Solomon 纠错（0-8 级） | 航运危险品清单、海关单据、航空登机牌、身份证明 | 数据容量巨大（超过 1KB 数据），相当于“便携式数据文件”，脱机承载完整结构化数据。 |
| **DotCode** | **AIM ISS DotCode (2019)** | 由离散点阵构成的矩阵码，无连续实线寻像边 | **高速自动化流水线**（如卷烟包/条高速激光打码、饮料瓶盖高速喷印） | 专为高速连续喷墨/点阵激光打标设计（速度超 500米/分），不受流水线高速晃动或单点畸变影响。 |
| **Aztec Code** | **ISO/IEC 24778:2008** | 中心“牛眼”寻像靶（Bull's-eye），纠错率 5%~95% 自定义 | 航空登机牌（IATA）、欧洲铁路车票 (UIC 918.3) | 无需周围静区（Quiet Zone），边缘磨损或裁剪不影响解码，只要中心牛眼完好即可识别。 |
| **MaxiCode** | **ISO/IEC 16023:2000** | 六角形蜂巢矩阵，中心同心圆寻像靶，固定物理尺寸（约 1x1 英寸） | UPS 物流包裹高速输送带分拣 | 专为高速 Conveyor 分拣设计，内置 Class/Zip/Country 定长主消息区与二级消息区。 |

### 3. 直接零件标识 DPM (Direct Part Marking) 规范

* **核心标准**：**ISO/IEC TR 29158:2011** (AIM DPM-2006)
* **工艺类型**：点针打标（Dot Peen）、激光刻蚀（Laser Etch）、化学腐蚀（Chemical Etch）、连续喷墨（Continuous Inkjet）。
* **质量评级关键指标**：
  * **CC (Cell Contrast)**：单元对比度（根据局部背景动态阈值计算）
  * **CM (Cell Modulation)**：单元调制比（单个黑白点相对于决策阈值的偏移度）
  * **CS (Cell Steering)**：单元中心偏离度（打点是否发生几何位移）
  * **MR (Min Reflectance)**：最小反射率裕度
  * **FPD (Fixed Pattern Damage)**：“L”型寻像边完整度
* **识读挑战与光学方案**：金属拉丝纹理、曲面高光反光、粗糙铸造面。工业读码器通常需结合同轴光（Coaxial）、低角度漫射环形光（Low-Angle Diffuse）、穹顶光（Dome Light）及偏振滤光。

## 三、 数据语法与传输外壳标准（数据层与协议层）

### 1. ISO/IEC 15434 传输语法外壳 (Envelope)

在高端离散制造（汽车、航天、军工）中，条码解码出的原始数据通常封装在 **ISO/IEC 15434:2019**（High capacity ADC media format）标准外壳中。

#### 核心协议报文结构

```
+-----------------------------------------------------------------------------------+
| 报头 (Header)         | 格式头 (Format Header) | 数据载荷 (Data Stream) | 报尾 (Trailer) |
| [ ) > <RS>            |  06 <GS>               | 1P...<GS>Q...<GS>S... | <RS> <EOT>     |
+-----------------------------------------------------------------------------------+
```

#### 控制字符定义 (ASCII Code)

* **`[)>`**：合规前缀（Message Prefix，3 字节 ASCII：`0x5B, 0x29, 0x3E`）
* **`<RS>` (Record Separator / ASCII 30 / `\x1E`)**：记录分隔符，界定报头、格式区与报尾。
* **`<GS>` (Group Separator / ASCII 29 / `\x1D`)**：组分隔符，用于切分变长数据段或不同字段。
* **`<EOT>` (End of Transmission / ASCII 04 / `\x04`)**：传输结束符。

#### 常见格式代码 (Format Indicators)

| 格式代码 | 对应标准体系 | 内容特征与用途 |
| :--- | :--- | :--- |
| **Format 05** | GS1 System (ISO/IEC 15418) | 内部由 GS1 应用标识符 (AI) 组织的数据，以 `<GS>` 分隔。 |
| **Format 06** | ASC MH10.8.2 / ISO/IEC 15418 | **制造业第一通用外壳**。内部由 Data Identifiers (DI) 组织的数据。 |
| **Format 07** | DoD Unique Item Identifier (UID) | 美国国防部资产唯一识别规范专用格式。 |
| **Format 12** | Text Element Identifiers (TEI) | 航空工业航材标识（ATA Spec 2000 传统格式）。 |

#### 真实原始码流示例 (Format 06)

```text
[)>\x1E06\x1D1PA10402\x1DQ1000\x1D1T20260819A\x1DS00891\x1E\x04
```
* **分解说明**：
  * `[)>\x1E06\x1D`：ISO 15434 Format 06 报头
  * `1PA10402`：DI 为 `1P`（供应商零件号），值为 `A10402`
  * `\x1DQ1000`：DI 为 `Q`（数量），值为 `1000`
  * `\x1D1T20260819A`：DI 为 `1T`（批次号），值为 `20260819A`
  * `\x1DS00891`：DI 为 `S`（序列号），值为 `00891`
  * `\x1E\x04`：记录结束符与传输结束符

#### Data Matrix 中的 Macro 05 / Macro 06 硬件级压缩
在 Data Matrix ECC 200 中，采用宏字码（Macro Codewords 236/237）进行物理存储压缩：条码中仅编码一个宏字码，硬件解码器在向上位机输出时，**自动展开为上述包含 `[)><RS>06<GS>` 和 `<RS><EOT>` 的完整 ASCII 码流**。

### 2. GS1 Application Identifiers (AI) 体系

遵循 **ISO/IEC 15418 / GS1 General Specifications**。AI 为 2 到 4 位数字前缀，用于标明其后数据的业务属性。

#### 核心常用 AI 字典表

| AI 前缀 | 业务含义 (Data Concept) | 格式定义 | 长度类型 | 字段结尾规则 |
| :--- | :--- | :--- | :--- | :--- |
| **(00)** | SSCC (系列货运包装箱代码) | `N2 + N18` | **定长 (18位数字)** | 紧接下一 AI，无需分隔符 |
| **(01)** | GTIN (全球贸易项目代码) | `N2 + N14` | **定长 (14位数字)** | 紧接下一 AI，无需分隔符 |
| **(02)** | 包装内所含 GTIN | `N2 + N14` | **定长 (14位数字)** | 紧接下一 AI，无需分隔符 |
| **(10)** | 批号 / Batch or Lot Number | `N2 + X..20` | **变长 (1-20位字符)** | 若后接其他 AI，**必须以 `<GS>` 结尾** |
| **(11)** | 生产日期 (YYMMDD) | `N2 + N6` | **定长 (6位数字)** | 紧接下一 AI，无需分隔符 |
| **(13)** | 包装日期 (YYMMDD) | `N2 + N6` | **定长 (6位数字)** | 紧接下一 AI，无需分隔符 |
| **(15)** | 最佳食用期 (YYMMDD) | `N2 + N6` | **定长 (6位数字)** | 紧接下一 AI，无需分隔符 |
| **(17)** | 有效截止日期 (YYMMDD) | `N2 + N6` | **定长 (6位数字)** | 紧接下一 AI，无需分隔符 |
| **(21)** | 序列号 / Serial Number | `N2 + X..20` | **变长 (1-20位字符)** | 若后接其他 AI，**必须以 `<GS>` 结尾** |
| **(240)** | 附加产品标识 | `N3 + X..30` | **变长 (1-30位字符)** | 若后接其他 AI，**必须以 `<GS>` 结尾** |
| **(310x)** | 净重（千克），x 表示小数位数 (0-5) | `N4 + N6` | **定长 (6位数字)** | 紧接下一 AI，无需分隔符 |
| **(400)** | 客户采购订单号 (PO Number) | `N3 + X..30` | **变长 (1-30位字符)** | 若后接其他 AI，**必须以 `<GS>` 结尾** |

> **关键规则**：
> 1. **人眼可读字符 (HRI)** 中使用小括号，如 `(01)06912345678901(17)261231(10)LOT2026A(21)SN9988`。
> 2. **物理条码解码码流中绝对不包含括号**，变长字段后直接填充 `<GS>` (`\x1D`)：
>    `01069123456789011726123110LOT2026A\x1D21SN9988`

### 3. ASC MH10.8.2 / ISO 15418 数据标识符 (DI) 体系

广泛应用于北美与欧洲汽车工业（AIAG/VDA）、航空航天、军工与电子制造业。

#### 常用工业 DI 字典表

| DI 前缀 | 标准英文定义 | 中文业务含义 | 典型值格式 |
| :--- | :--- | :--- | :--- |
| **P** | Part Number | 客户零件号 | 变长字母数字 (如 `PA10402`) |
| **1P** | Supplier Part Number | 供应商零件号 | 变长字母数字 |
| **30P** | Secondary Part Number | 辅助零件号/备用号 | 变长字母数字 |
| **Q** | Quantity | 数量（件数/包装数量） | 纯数字（如 `Q1000`） |
| **S** | Serial Number | 唯一序列号/单品追溯码 | 变长字母数字 (如 `S00891`) |
| **1S** | Supplier Serial Number | 供应商序列号 | 变长字母数字 |
| **3S** | Package / Box ID | 外包装箱编号 | 变长字母数字 |
| **4S** | Master Pallet ID | 母托盘 / 栈板标识 | 变长字母数字 |
| **T** / **1T** | Traceability / Lot Number | 批次号 / 追溯批号 | 变长字母数字 (如 `1TLOT2026A`) |
| **V** | Vendor / Supplier ID | 供应商代码 (DUNS/Cage) | 5-9 位字母数字 (如 `V12345`) |
| **17V** | Supplier CAGE Code | 美国政府/军工供应商机构码 | 5 位字母数字 |
| **1V** | Parent Company Vendor Code | 母公司供应商代码 | 变长字母数字 |
| **K** | Customer Order Number / PO | 客户采购订单号 | 变长字母数字 |
| **14K** | Purchase Order Line Number | 采购订单行号 | 纯数字 |
| **D** / **6D** | Date Code (YYMMDD / YYYYMMDD) | 制造日期 / 包装日期 | 6-8 位数字 (如 `6D20260819`) |
| **E** | Engineering Change Level | 工程变更版本 / 设变号 | 变长字母数字 (如 `EREV02`) |
| **L** | Location / Dock Code | 库位代码 / 卸货道口号 | 变长字母数字 |

#### 工业 DI 数据的三种典型组装形态

1. **ISO 15434 结构化封装 (Standard Structured Envelope)**：
   * 样例：`[)>\x1E06\x1D1PA10402\x1DQ1000\x1DS00891\x1E\x04`
   * 特征：使用标准控制字符 `\x1D` 强切分。
2. **自定义字符显式分隔 (Delimited Stream)**：
   * 样例：`PN-A10402@L260818A@2634@Q1000@LN01@00891` 或 `P:A10402|Q:1000|S:00891`
   * 特征：使用 `@`, `|`, `-`, `;`, `/` 等工控常见符号切分。
3. **紧凑无分隔拼接 (Concatenated Stream)**：
   * 样例：`1PA10402Q10001TLOT2026S00891`
   * 特征：无标点，DI 直接与数值粘连，依赖前缀树自动机或正则前瞻断言匹配。

## 四、 行业垂直应用规范

### 1. 汽车工业 (Automotive)

* **AIAG (北美汽车工业行动小组)**：
  * **AIAG B-10** (零部件标签规范) / **AIAG B-14** (DPM 追溯规范)。
  * 采用 Code 39 或 Data Matrix ECC 200，ISO 15434 Format 06。必须包含 `P`（零件号）、`Q`（数量）、`V`（供应商代码）、`S`（序列号）。
* **VDA (德国汽车工业协会)**：
  * **VDA 4902**（传统一维箱标签）与 **VDA 4994 (Global Transport Label / GTL)**。
  * 采用 2D Data Matrix 或 PDF417，定义单件箱（Single）、主包装箱（Master）、混合托盘（Mixed Master）。
  * 核心 DI：`1J`（单包装唯一 ID / License Plate）、`11D`（生产日期）、`20P`（客户物料版次）。
* **JAMA / JAPIA (日本汽车工业协会)**：
  * 广泛采用 QR Code Model 2，用于丰田等日系供应链的精益生产看板（Kanban）。

### 2. 航空航天与国防军工 (Aerospace & Defense)

* **ATA Spec 2000 Chapter 9 (AIDC - 自动识别与数据采集)**：
  * 全球商用飞机（波音、空客等）零部件及航材永久性标识（DPM）的唯一行业权威。
  * 强制采用 Data Matrix ECC 200 + ISO 15434 Format 06。
  * 核心字段：`CAG` (CAGE Code / 商业与政府实体代码)、`1P` (零件号)、`1S` (序列号)。
* **MIL-STD-130 (美国国防部 IUID / UID 唯一物料标识)**：
  * **Construct 1 (基于企业内序列号唯一)**：CAGE Code (`17V`/`18S`) + Serial Number (`S`)
  * **Construct 2 (基于零件号+序列号联合唯一)**：CAGE Code (`17V`) + Original Part No (`1P`) + Serial Number (`S`)
  * 必须使用 ISO 15434 Format 06 或 Format 07 封装。

### 3. 半导体与电子制造 (Semiconductor & Electronics)

* **SEMI (半导体设备与材料国际标准)**：
  * **SEMI T7-0302**：300mm 硅片晶圆背面直接激光打标（Laser Mark）规范，8 字符 Data Matrix。
  * **SEMI T8 / T9**：晶圆载具 (FOUP / Cassette) 外部标识规范。
  * **SEMI T10**：引线框架 (Lead Frame) 微型二维码标识规范。
  * **SEMI G71 / G83**：PCB 表面与 IC 封装体超微型 2D DPM 标刻。
* **IPC (国际电子工业联接协会)**：
  * **IPC-1782**：电子元器件与组装件的全面追溯标准（Critical Levels I~IV），规定了 PCB 上 1.5mm x 1.5mm 级超微型 Data Matrix 码的编码与数据字典。

### 4. 医疗器械与医药监管 (Medical Device & UDI)

* **UDI (Unique Device Identification - 唯一医疗器械标识)**：
  * 法规依据：美国 FDA UDI、欧盟 MDR/IVDR、中国国家药监局 (NMPA) 医疗器械唯一标识法规。
  * 结构组成：
    $$\text{UDI} = \text{DI (设备标识符 - 静态)} + \text{PI (生产标识符 - 动态)}$$
  * **三大发码机构体系**：
    1. **GS1**：`DI = (01) GTIN`，`PI = (17) 灭菌有效期 + (10) 生产批号 + (21) 序列号`
    2. **HIBCC (健康行业商业通信委员会)**：前缀为 `+` 的 LIC 语法（如 `+A999123451/$$426081910A1234#`）。
    3. **ICCBBA (ISBT 128)**：专用于血液制品、干细胞、人体组织器官移植。

### 5. 烟草与高速自动化物流

* **中国烟草总公司“一打三追溯”**：
  * 件烟 32 位条码（企业代码 4位 + 规格 4位 + 机台 2位 + 班次 1位 + 年月日 8位 + 流水号 5位等）。
  * 1200包/分钟高速产线采用 **DotCode** 激光/喷墨打码与飞拍识别。
* **现代快递电商物流**：
  * 菜鸟裹裹 / 顺丰 / 丰巢面单三段码（大头笔分拣码）与路由条码（Code 128 / PDF417 / 混排 QR）。

## 五、 硬件解码器特性与控制符码流（底层 I/O 层）

### 1. ISO/IEC 15424 AIM 码制前缀标识

工业扫码器可开启 AIM ID 输出，在解码内容最前端输出 3 字节标识 `]c m`：

| AIM ID 前缀 | 对应物理码制与传输特征 |
| :--- | :--- |
| **`]d1`** | Data Matrix (ECC 200, 遵循 ISO 15434 / GS1 标准) |
| **`]d2`** | GS1 Data Matrix (第 1 位为 FNC1) |
| **`]d6`** | Data Matrix (使用 ISO 15434 Macro 05/06 封装) |
| **`]C0`** | 标准 Code 128 (无 FNC1) |
| **`]C1`** | GS1-128（条码首字符为 FNC1） |
| **`]Q1`** | GS1 QR Code |
| **`]Q2`** | 2005 标准 QR Code (原始字节流) |
| **`]e0`** | GS1 DataBar |
| **`]I0`** | Interleaved 2 of 5 (无校验位传输) |
| **`]I1`** | Interleaved 2 of 5 (带 Modulo 10 校验并传输) |
| **`]A0`** | 标准 Code 39 |

### 2. 不可见控制字符在不同模式下的传输表现

| 控制字符 | ASCII 码 | 十六进制 | 串口 / TCP 模式 (Serial / VCP) | USB 键盘仿真模式 (HID POS / Wedge) |
| :--- | :--- | :--- | :--- | :--- |
| **GS** (Group Separator) | 29 | `\x1D` | 原始字节 `0x1D` 正常传输 | **极易丢失或变形**！常被转译为 `F8`、`<Enter>`、`<Tab>` 或静默丢失 |
| **RS** (Record Separator) | 30 | `\x1E` | 原始字节 `0x1E` 正常传输 | 通常被 Windows 键盘驱动丢弃 |
| **EOT** (End of Transmission) | 04 | `\x04` | 原始字节 `0x04` 正常传输 | 通常被丢弃 |
| **CR / LF** | 13 / 10 | `\x0D \x0A` | 回车换行符 | 映射为键盘回车键（Enter） |

## 六、 对条码正则/规则推断工具的设计启示与边界判定

结合工业标准全景，条码规则引擎的职责分工与架构边界如下：

```
+-------------------------------------------------------------------------------+
|                       条码解析与验证的分工边界矩阵                            |
+------------------------------------+------------------------------------------+
|  正则/模式推断引擎 (Regex Engine)  |   业务层 / 专用协议解析器 (Parser Logic) |
+------------------------------------+------------------------------------------+
| 1. ISO 15434 外壳格式拦截           | 1. EAN-13 / UPC-A / Modulo 43 加权模运算 |
| 2. 字段定长 / 变长范围边界校验     | 2. 多 GS1 AI 动态变长混排状态机          |
| 3. 字符集过滤 (大写字母/纯数字)    | 3. 跨字段业务逻辑 (如过期日期 > 生产日期)|
| 4. 显式定界符分段切分 (@, |, -, /) | 4. 数据库工单/料号存在性核验             |
| 5. DI 前缀有效性过滤 (1P, Q, S, 1T)| 5. 键盘仿真模式下丢失控制符的协议重构    |
+------------------------------------+------------------------------------------+
```

1. **格式正则层（模式推断引擎）**：
   - 极其擅长定长切分、显式分隔符分段、字符分类提取（`[A-Z]` / `\d`）、DI 前缀拦截与 ISO 15434 外壳识别。
   - 应当为工程师自动推断出具备良好泛化能力、拦截格式越界（如长度不对、混入小写字母/非法标点）的候选正则。
2. **业务与协议层**：
   - 算术模校验（Luhn / Modulo 10 / Modulo 43）、日历有效性校验、以及多 AI 动态状态机，需通过业务代码或插件式专用解析器完成，解耦设计是最优解。

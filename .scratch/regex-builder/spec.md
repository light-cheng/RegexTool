# 条码正则生成器（Regex Builder）

Status: implemented（2026-08-17 工单 01–09 全部完成并提交；UI 待用户双击运行确认）

## Problem Statement

配置条码解码软件的工程师经常需要为工厂条码编写正则规则。工厂条码由多个字段拼成（料号、批号、日期、批次、序号、周号…），可能用普通分隔符连接（如标点或 ASCII 29 控制字符 GS）、采用工业标准 Data Identifier（数据标识符 / DI，如 P/1P 零件号、Q 数量、S 序列号、1T 批次号等）前缀直接拼接/包络连接，或直接拼接成一条长串。手写这些正则很容易出错：字段边界找不准、字符类型/长度写错、某条异常条码漏进去或合法条码被挡掉。工程师希望：给出若干条格式相同、内容略有变化的条码（正例），再给出若干条不该被识别的条码（反例），工具自动归纳出最优正则，并自动验证正例都能命中、反例都被排除、字段都能正确捕获。

## Solution

一个便携的单文件 Windows 桌面工具（C++ 编译的单个 exe，免安装、完全离线）。工程师在「项目」里按条贴入多条正例与反例（点「+」逐条添加，或批量粘贴自动拆分）；工具自动识别条码的分段结构（按分隔符/控制字符/工业 DI 前缀标记切分，或由用户指定每段长度），为每一段推断规则（固定文本原样保留，变化部分归纳为字段：字符类型 + 长度），生成多个候选正则，并对每条例子执行验证（正例整串匹配 + 字段捕获值一致，反例整串不匹配），再按「越简单越靠前」排序展示。每条候选正则都附逐例验证结论（✓/✗，✗ 指出卡在哪一段）；提供「自测框」随手贴一条条码立即判定；最终输出一段可一键复制、风格与目标解码软件一致的正则文本。项目可保存/加载（exe 旁的小文件），支持「+」新建多个项目；含可选段的格式拆成独立项目配置。

## Implementation Decisions

- **架构形态**（ADR-0001）：C++ 编写的单个免安装 exe、完全离线、无外部依赖（不含大模型/网络调用）。
- **唯一核心接缝**：纯核心引擎，不依赖 UI。输入为项目定义（正例、反例、分段配置），输出为候选正则列表及每条例子的验证结论（是否通过、失败时卡在哪一段、各字段捕获值）。UI 与项目文件存取是围绕它的薄壳。
- **分段模式**三种：
  ① **按分隔符/控制字符/DI 前缀自动切分**：
     - 分隔符可以是可见标点（`@`、`|`、`-`、`_`、`/`、`#`、`;` 等）；
     - 工业标准不可见 ASCII 控制字符（如 ISO/IEC 15434 Format 06 中的 **Group Separator GS / ASCII 29 / `\x1D`**、Record Separator RS / ASCII 30、EOT 等）以及包络头（如 `[)>06`）；
     - 工业界广泛使用的 **Data Identifier（数据标识符 / DI）** 前缀（ASC MH10 / ISO/IEC 15418 / GS1 AI，如 `P`/`1P` 零件号、`Q` 数量、`S` 序列号、`1T`/`T` 批次号、`K`/`14K` 采购单号、`4K` 订单行号、`V` 供应商代码、`D` 日期代码、`3S`/`4S` 包装箱号等），支持无标点直连拼接（如 `1P12345678Q1001TLOT2024AS98765`）或带 GS 分隔符的混合模式；
     - 取「对所有正例一致」的分段解释。
  ② **按长度手动切分**：无分隔符/无 DI 前缀时由用户告知每段长度；
  ③ **单段模式**：只有一整段时不配置分段。用户可手动覆盖/调整任意一段的规则。
- **段规则推断**：所有正例相同的部分 → 固定文本原样保留（含分隔符、控制字符与标签/DI，如 `@`、`GS`、`1P`、`Q`、`1T`、`S`、`PN`、`DT2026`）；会变化的部分 → 字段：字符类型从例子里推断（纯数字 → `\d`；字母 → `[A-Z]`；混合 → `[A-Z0-9]`，大小写按例子推断）+ 长度（全部一致 → `{n}`；有变化 → `{min,max}`）。字段名沿用固定标签与 DI 前缀。整段恒定的段默认保留为固定文本，用户可手动将其提升为字段。
- **输出正则风格**（以用户真实例子校准）：整串锚定 `^…$`，量词 `\d{n}`，标签与分隔符原样；**不生成捕获组**——字段是工具侧的分段模型，正则本身无分组，保证与 std::regex 等常见 C++ 引擎兼容。
- **候选生成**：按严格程度产出多个变体（如长度精确 vs 放宽、字符类收紧 vs 放宽）；先过滤掉「有例子不过关」的，剩余按简单程度排序，第一个为推荐。展示 top N（3–5 个）。
- **验证语义**：正例 = 整串锚定全匹配 + 每个字段捕获值与它在正例中的实际值逐一相等；反例 = 整串不匹配——分段结构不同的天然排除，分段相同但内容不合规（如数字段混入字母）由字段规则排除。每条例子给出独立结论，失败时指明是哪一段。
- **验证执行**：在工具内用与输出同风格的正则引擎执行验证，带超时保护（生成的表达式均为简单线性结构，ReDoS 风险低，但仍设守卫）。
- **UI**：正例/反例输入区为动态添加——初始一条，点「+ 正例」/「+ 反例」逐条新增，每条可 ✕ 删除，并排成列、多则自动换行；另支持批量粘贴自动拆成多条。候选列表可展开查看逐例结论；「自测框」贴任意条码立即判定；分段规则表与最终正则并列展示；一键复制按钮。
- **项目**：命名保存/加载（exe 旁的小文件），「+」新建项目；含可选段的格式按用户要求拆成独立项目。
- **兜底**：所有候选都不过时，列出最接近的候选并高亮「卡住了哪条例子」，不静默返回未验证的结果。
- **输入卫生**：正例首尾的空格/异常字符给出警告（真实数据中出现过：第 4 条正例末尾带空格）；条码中的非 ASCII 字符按固定文本原样保留。
- **界面语言**：中文；生成的正则文本为通用语法。

## Testing Decisions

- 只测外部行为，不测实现细节：喂入项目定义（正例/反例/分段配置），断言产出的候选正则文本与逐例验证结论。
- 唯一测试接缝：核心引擎的公开接口。
- 典型用例（验收锚点）：
  - 用户提供的 5 条真实正例必须产出 `^PN\d{4}@BN\d{4}@DT2026@LT\d{4}@SQ000\d@WK\d{2}$`（如实推断：样本 `SQ0001..SQ0005` 前三位 `000` 全同 → 视为固定文本），且 5 条正例全部通过、字段捕获值逐一正确。用户手写目标 `SQ\d{4}` 经工单 05「恒定段提升为字段」达成（提升 `@SQ000` 后与相邻 `\d` 合并）。
  - 反例两类都要覆盖：结构完全不同的（整串匹配失败）、分段相同但内容不合规（如 PN 段出现字母，验证结论须指向 PN 段）。
  - 工业标准 Data Identifier（ASC MH10 DI 前缀直连模式，如 `1P12345678Q1001TLOT2024AS98765`）能正确识别 `1P`、`Q`、`1T`、`S` 等 DI 标记并分段，产出 `^1P\d{8}Q\d{3}1T[A-Z0-9]{8}S\d{5}$`。
  - ISO/IEC 15434 Format 06 语法带 GS（ASCII 29 / `\x1D`）控制字符与 DI 前缀的条码能正确识别分隔符并生成对应正则。
  - 无分隔符时按用户指定的每段长度正确切分。
  - 正例带尾随空格时产生警告。
- 框架：与项目同语言的轻量单元测试（无外部依赖，保持便携性）；当前仓库为绿地，无既有测试可参照（先例：无）。

## Out of Scope

- 网络/云端/大模型方案（ADR-0001 已否决）。
- 团队共享/协作、格式库分发。
- std::regex 之外的引擎特性（lookbehind、backreference、命名捕获组等）——本工具不生成也不需要。
- 自动写入/对接目标解码软件——输出为可粘贴文本。
- 条码图像解码/扫码——工具只处理解码后的字符串。
- 非 Windows 打包——代码保持可移植，但交付物定位为 Windows 单 exe。
- 字段校验和/校验位（如 GS1 校验码）验证。
- 可选段在同一个正则内的支持——按已确认设计，拆成独立项目处理。

## Further Notes

- 设计来自一轮 grilling 会话（grill-with-docs）；术语见根目录 `CONTEXT.md`（正例、反例、分隔符、数据标识符 DI、字段、分段、项目、候选正则、验证），架构决定见 `docs/adr/0001-portable-offline-cpp-exe.md`。
- 输出风格已用用户真实例子校准；5 条真实正例 → 目标正则是一个明确的验收锚点。注意 SQ000 决策（2026-08-17，选项 a）：引擎如实推断 `SQ000\d` 而非用户手写的 `SQ\d{4}`，纯数据驱动无法识别补零；恒定段提升（工单 05）是达成手写目标的机制。
- 建议实现顺序：先核心引擎（分段 → 规则推断 → 候选生成 → 验证），再接 UI 与项目存取。
